# ns8-warpgate

A [NethServer 8](https://github.com/NethServer/ns8-core) module for [Warpgate](https://github.com/warp-tech/warpgate) - a smart SSH, HTTPS and MySQL bastion that requires no client-side software.

## Features

- Smart SSH bastion with web-based terminal access
- HTTPS reverse proxy capabilities
- MySQL database proxy support
- Web admin interface for user management
- No client software installation required
- Automatic SSL certificate management via Let's Encrypt

## Install

Instantiate the module with:

```bash
add-module ghcr.io/geniusdynamics/warpgate:latest 1
```

The output will return the instance name:

```json
{
  "module_id": "warpgate1",
  "image_name": "warpgate",
  "image_url": "ghcr.io/geniusdynamics/warpgate:latest"
}
```

## Configure

Let's assume that the warpgate instance is named `warpgate1`.

Launch `configure-module`, by setting the following parameters:

- `host`: a fully qualified domain name for the application
- `http2https`: enable or disable HTTP to HTTPS redirection (true/false)
- `lets_encrypt`: enable or disable Let's Encrypt certificate (true/false)

Example:

```bash
api-cli run configure-module --agent module/warpgate1 --data - <<EOF
{
  "host": "warpgate.domain.com",
  "http2https": true,
  "lets_encrypt": false
}
EOF
```

The above command will:

- start and configure the warpgate instance
- configure a virtual host for Traefik to access the web UI

On first start Warpgate runs `unattended-setup`: it creates its configuration
and database in the `data` Podman volume, with an `admin` user. The `host`
value is used as Warpgate "external host" at that time only: if you change
the host later, update it in the Warpgate admin UI too.

### Admin password

The password of the initial `admin` user is generated by `add-module` and
stored in `state/warpgate.env` (included in the module backup):

```bash
runagent -m warpgate1 sh -c 'grep WARPGATE_ADMIN_PASSWORD "$HOME/.config/state/warpgate.env"'
```

Change it from the Warpgate admin UI after the first login. The stored value
is only used by the first-run setup.

### Ports

- Web UI (HTTPS, self-signed certificate): published on `127.0.0.1` and
  exposed by Traefik at `https://<host>/`. Traefik terminates the public TLS
  and re-encrypts to the backend without verifying its self-signed
  certificate.
- SSH bastion (container port 2222) and MySQL proxy (container port 33306):
  raw TCP protocols that Traefik cannot route. They are published on the
  node on the second and third TCP ports reserved for the module (see
  `TCP_PORT_SSH` and `TCP_PORT_MYSQL` in `runagent -m warpgate1 env`). Open
  them in the node firewall if clients must connect from outside.

## Get the configuration

You can retrieve the configuration with

```bash
api-cli run get-configuration --agent module/warpgate1
```

## Update

Update your instance

```bash
api-cli run update-module --data '{"module_url":"ghcr.io/geniusdynamics/warpgate:latest","instances":["warpgate1"],"force":true}'
```

## Uninstall

To uninstall the instance:

```bash
remove-module --no-preserve warpgate1
```

## Debug

### Check Environment Variables

The module runs under an agent that initializes environment variables in `/home/warpgate1/.config/state`. To verify them:

```bash
runagent -m warpgate1 env
```

### Access the Module Environment

Become the runagent for testing scripts with all environment variables loaded:

```bash
runagent -m warpgate1
```

### Container Debugging

First, enter the module environment:

```bash
runagent -m warpgate1
```

List running containers:

```bash
podman ps
```

Show the Warpgate logs (the upstream image is distroless, it has no shell):

```bash
podman logs warpgate
```

The service logs are available with `journalctl` as well:

```bash
runagent -m warpgate1 journalctl --user -u warpgate.service
```

## Testing

This module uses the NS8 standard testing infrastructure: the `Test module`
workflow runs the [Robot Framework](https://robotframework.org/) suite in
`tests/` on a QEMU NS8 cluster, after the `Publish images` workflow has built
the module images. To run the suite locally, refer to the [Running tests
locally](https://github.com/NethServer/ns8-github-actions/blob/v1/README.md#running-tests-locally)
section of the ns8-github-actions README.

## Updating Warpgate

Warpgate is pulled from `ghcr.io/warp-tech/warpgate`, pinned in the
`org.nethserver.images` label set by `build-images.sh` (currently `0.30.4`;
upstream image tags have no `v` prefix). Bump the `warpgate_image` variable
there, then run the test workflow.
